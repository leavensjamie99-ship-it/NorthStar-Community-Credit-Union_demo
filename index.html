IT Documentation Hierarchy

GOVERNANCE MODEL

The four registers organize IT documentation by purpose and level of detail. Policies establish direction and requirements; standards define required rules or minimum expectations; procedures describe how a process is performed; and work instructions provide detailed task-level steps.

Policy→Standard→Procedure→Work Instruction

Why the Registers Matter

AUDIT READY
  • Central visibility — identify what documentation exists and its current status.
  • Ownership — identify document owners, authors and approvers.
  • Version control — maintain revision history and the reason for changes.
  • Review management — track effective and next-review dates.
  • Evidence — link document changes to supporting ticket or change evidence.

Domain 1 · User Access Management — Termination

The second control demonstrates termination notification, timely access removal, asset recovery, verification and audit testing.

IAM-02

IAM-02 — Terminated User Access Removal

PER EVENT
Control ObjectiveEnsure terminated-user access is disabled and removed within the required timeframe to prevent continued unauthorized access.
Control OwnerIT Service Desk / IT Operations
Control FrequencyPer termination event
Control TypePreventive + Detective
Primary EvidenceTermination ticket, child tickets, User Access Matrix, access-removal verification and completion timestamps

Timing control: For an immediate termination, access is disabled immediately. For a scheduled termination, required access removal is completed by 11:00 PM on the completion date provided. The NorthStar demo uses this timing requirement as an audit-test criterion.
